Computes which fields of a "fat object" parameter are actually read and written across the method's call graph, and records the result in the Javadoc as @param name reads {a, b, c} writes {d} — to guide extraction of thin DTOs.

The analysis is transitive and honest about blind spots: parameters that reach whole-object sinks (serialization, a script engine, whole-object marshalling like toXML) are annotated reads {ALL}; opaque boundaries are annotated reads {?}.

Offered on any parameter whose type declares enough instance fields. Invoke it explicitly (Alt+Enter); it runs behind a cancelable progress bar because the transitive analysis is too expensive to run on-the-fly.
